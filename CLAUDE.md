# ASIT — architecture notes for Claude Code

Electron (electron-vite + React + TS) AI-first browser with an agent core; the original study tools (timer, lockdown, SM-2 review) live behind `Settings.studyEnabled`. Windows and macOS.

**Platform rule:** anything OS-specific goes behind a `process.platform` check with a working path for both, or degrades to a clear "not available here" — never a crash. Windows-only by nature: embedded native windows (`appwindows.ts`, Win32 `SetParent`) and auto-update (macOS needs a signed app). `npm run smoke` is the cross-platform gate and runs on both in CI.

## Structure

- `src/shared/` — `types.ts` (all domain types), `ipc-contract.ts` (every IPC channel name; single source of truth)
- `src/main/db/` — better-sqlite3, WAL, numbered migrations via `PRAGMA user_version` (append-only; never edit an existing migration)
- `src/main/services/` — one service per domain: `tasks` (CRUD, folders, CLAUDE.md, scratchpad, privacy), `resources`, `panes` (WebContentsView manager + page bridge), `claude` (CLI spawn + NDJSON parse), `chat`, `assistant` (global haiku bar), `timer` (stopwatch/pomodoro state machine), `lockdown`, `questions` (job queue + SM-2), `actions` (AI app-control protocol), `accounts`, `library`, `transfer` (backup zip), `usage` (token/cost log), `settings`, `companion` (phone PWA server + web push), `jarvis` (universal agent: one core, callback-based, surfaces = desktop panel/phone/voice-later), `bus` (in-process pub/sub so services never import each other for events)
  Plus the browser-first additions: `workflows` (first-class automations: DB entities with params, action/model/confirm/wait_for/assert steps, durable run history — see invariant 21), `bookmarks` (global, agent-unreachable like `history`), `search` (Settings-driven search-engine URLs; shared table in `src/shared/search.ts`), `context` (the owner-scoped pane-context header prepended to every agent turn)
- `src/preload/index.ts` — typed `window.asit` bridge; `index.d.ts` mirrors it for the renderer
- `src/renderer/src/` — React UI; zustand store; screens `Home` / `Workspace`; `browser/` is the SHARED browser chrome (TabStrip, BrowserToolbar, FindBar, NewTabPage, useTabs/useFindInPage/usePaneGeometry, tabContextMenu) consumed by both `ScratchBrowser` (flat tabs, persisted in the scratch task's `layout_json`) and `PaneGrid` (two-slot workspace layout) — never re-duplicate this chrome. One assistant panel (`AssistantPanel`, agent/quick scopes over the unchanged JARVIS_*/ASSISTANT_* protocols), `AutomationsModal` (workflows + schedules UI), `WorkspaceSwitcher` (native-menu tab-group switcher in every header)

## Load-bearing invariants

1. **Task folder = AI context.** Every task owns `Documents\ASIT\tasks\<slug>-<id>\` with an auto-maintained `CLAUDE.md`. All `claude` CLI spawns use `cwd = task folder`. Resource changes must call `tasks.refreshClaudeMd(taskId)`.
2. **WebContentsViews paint above ALL renderer DOM.** Any overlay/modal must hide views first — always use the `useOverlay()` hook (`src/renderer/src/hooks/useOverlay.ts`), never roll your own modal. Corollary for persistent chrome: a floating indicator over the pane area is invisible, so status UI belongs in the header row (`StatusCluster`) and anything docked must reserve layout space (`body.assistant-open` margin) — never reserve a strip just to park a floating widget.
3. **Timer + lockdown live in main.** Escape friction (30s hold, phrase) is validated in main (`timer.holdRelease`/`phraseRelease`); renderer UI is display-only. Never persist lockdown state. Agents may `start_focus` (user-prompted, refused in `runFlow`) but **no verb that stops/releases a session exists anywhere in the action protocol — absence, not a permission check; never add one** (`ASIT_SMOKE_SECURITY=1` asserts the absence).
4. **Claude CLI**: resolved at `%USERPROFILE%\.local\bin\claude.exe` (NOT on PATH), override via settings. `stream-json` requires `--verbose`. Prompts go via stdin. Chat spawns with `--allowedTools "Read(**),Glob,Grep(**),Edit(**),Write(**)"` — ALL file access is cwd-scoped to the task folder (`**` patterns verified to deny absolute paths outside cwd); the global assistant gets read-only `Read(**),Glob,Grep(**)` with cwd = tasks root. Private tasks (invariant 8) rely on this scoping.
5. **User files are never hard-deleted** — task deletion moves folders to `tasks\.trash\`.
6. **Agent app-control protocol** (`src/main/services/actions.ts`): chat spawns get `Edit(**),Write(**)` (cwd-scoped) and drive the app by appending JSON lines to `<task>\.asit\actions.ndjson` (open/add_url/add_questions/set_task); main watches the file and executes new lines, pushing `app:event` to the renderer. The protocol is documented for the model inside each task's generated CLAUDE.md (see `tasks.writeClaudeMd`). NotesEditor live-reloads external edits via `notes:watch`. **Pane ownership**: every pane is stamped with the task that opened it (`panes.open(id, target, ownerId)`), and every AI-facing PaneManager method (snapshotAll, interact, click/fill by label, key/type, navigate, existsCondition) REQUIRES the acting task's id and filters to owned panes — panes are parked across navigation, so without this a workspace agent could read or drive another workspace's (or the scratchpad's) tabs. Never add an AI-reachable pane method without the owner parameter; `ASIT_SMOKE_PANES=1` proves the boundary.
7. **Account logins** (`src/main/services/accounts.ts`): all embedded panes share `persist:asit-browse`; the accounts modal (first-run + Settings) opens provider login windows on that partition. Chrome session import is impossible (app-bound cookie encryption) — do not attempt it.
8. **Private (no-AI) tasks**: `tasks.ai_disabled=1` folders live under `Documents\ASIT\private\` — physically outside every AI cwd (tasks root, task folders). Chat/generation/grading/assistant/index/export must all exclude them; trash lives at `Documents\ASIT\.trash` (also outside). Never weaken this to a prompt-level exclusion.
9. **Smoke tests never touch real user data** — they run with their own userData and a temp documents dir; keep it that way when adding smoke modes.
10. **Keyboard focus is a ring, not DOM order.** `hooks/useFocusRing.ts` (installed once in `App.tsx`) owns F6/Shift+F6, Ctrl+1…9, Ctrl+K/Ctrl+L. **Tab is deliberately NOT ours** — it belongs to whatever has focus, so form fields tab in order; taking it meant a focused page never saw it. New panels must declare themselves with `data-focus-zone` (+ `data-focus-pane` for a WebContentsView, `data-focus-target`/`data-focus-body` to pick the control) — nothing else is a tab stop. Focused pages swallow keys, so `panes.ts`'s `before-input-event` replays those shortcuts as `APP_EVENT`s; main only focuses panes (`panes:focus`).
11. **Companion server trusts nothing but the token.** `services/companion.ts` binds 127.0.0.1 only (reachability = `tailscale serve`, never LAN/internet); every /api and /ws request needs the pairing token (constant-time compare); static serving is a filename whitelist, never a path join of client input; push payloads go through Web Push (E2E-encrypted by RFC 8291). Cross-service events ride `bus.ts` — never import companion from another service. `ASIT_SMOKE_COMPANION=1` proves the gates.
12. **Jarvis is the only agent with `workspace` re-targeting.** The universal agent lives in a hidden archived task (slug `jarvis`, like the scratchpad), runs with cwd = tasks root, and acts through the standard action protocol plus an optional `"workspace":"<name>"` field that re-executes the action AS that workspace (same pane ownership, same folder scope). `executeAction` refuses the field for any other taskId, and `resolveWorkspace` never matches private or archived tasks. Its session is bounded (rolling resume, 10-min idle expiry, briefing re-primes fresh sessions). `ASIT_SMOKE_JARVIS=1` proves targeting, refusal, private-unreachability, and a cross-workspace CLI read.
13. **Agent containment (untrusted-content threat model).** Agents read attacker-controllable content (web snapshots, PDFs, notes) while holding logged-in browser sessions, so treat every AI-reachable side-effect as a potential injection channel: `navigateFlow`/window.open/`shell.openExternal` are http(s)+mailto only (no `file:`/scheme handlers); `navigate` toasts the FULL url (exfil hides in the path, not the host); CLAUDE.md is regenerated from the DB before every chat spawn (caps stored injection to one turn) and frames notes/pages/PDFs as UNTRUSTED DATA; the Jarvis briefing does the same and restricts `send_whatsapp` to the current user message only; `send_whatsapp` + `workspace` re-targeting are Jarvis-only, and `runFlow` (no model in the loop) refuses both. `ASIT_SMOKE_SECURITY=1` locks all of this. Residual, un-fixable-without-killing-features risks (documented, not pretended away): an injected agent driving ITS OWN workspace's logged-in panes, navigate-as-exfil, Jarvis send_whatsapp, and coding-mode Bash (full-trust, confirm-gated).
14. **Guardrails are enforced in main, from data the model never controls** (`src/main/services/guardrails.ts`). Three walls, none of them prompt-level: (a) **protected topics** — `blockedTermIn` refuses the search outright in `quickFetchInner` (the page is never loaded, so no text exists to leak) and `filterSensitiveLines` strips matching result lines so a benign query can't surface a tax/password mail; settings terms ADD to `SENSITIVE_DEFAULTS`, they never replace them. (b) **sending is deny-by-default** — `authorizeSendsFromUserMessage` parses the USER's current message (called at the top of `chat.ts`/`jarvis.ts` turns, cleared on result); `send_whatsapp` and every mail Send control check `sendAuthorized`, with email needing a mail word AND a send verb. Reading/searching/summarizing/**drafting** stay unrestricted — only the irreversible act is gated. (c) **mail-UI Send is blocked at the click/keystroke layer** (`panes.ts` `interact`/`clickByLabel`/`keyToPage`/`sendKey`), because the real risk is an agent clicking Send in the Gmail tab the user is already signed into. Never gate a send by asking the model to behave; add the check here. `ASIT_SMOKE_SECURITY=1` locks all three.
15. **Terminals: agents may read, never type** (`src/main/services/terminal.ts`). Terminal panes are real ptys (ConPTY via `@lydell/node-pty`, prebuilt — the stock `node-pty` can't build here) spawned with `cwd` = the task folder. The write path (`writeFromUser`) is reachable ONLY from the focused xterm view via `TERMINAL_WRITE`; no action, flow, or service may call it, and `actions.ts` imports `readForAgent` alone. **There is no agent write verb anywhere in the protocol — this is absence, not a permission check**, so never add one. Reading requires per-workspace opt-in (`tasks.terminal_ai_read`, default 0, refused for private workspaces), is owner-scoped, is refused inside `runFlow` and refused for Jarvis `workspace` re-targeting (a shell's scrollback never crosses workspaces), and its output is ANSI-stripped, capped, and run through `filterSensitiveLines` (invariant 14 — shells print tokens). The verb is documented in CLAUDE.md only while the flag is on. Terminals are killed on task delete, privacy move, and quit. `ASIT_SMOKE_TERMINAL=1` proves all of it against a live pty. Honest limit: this contains the MODEL, not the shell — a terminal the user opens runs with their full privileges.
16. **Credentials never reach a model** (`src/main/services/vault.ts`). The password vault lives in `userData` (`%APPDATA%sitault.json`), encrypted with `safeStorage` (DPAPI, bound to the OS account) — physically outside every agent cwd, like private workspaces. There is no action verb, no flow verb and no agent-reachable IPC; autofill is driven only by the pane preload when the USER focuses a login field, matches on EXACT origin (no subdomain wildcards), and never auto-submits. The capture script in `panes.ts` replaces `type="password"` / one-time-code values with `[hidden credential — filled]` before any snapshot reaches an agent — **that masking is load-bearing now that autofill puts real secrets in those fields.** Never mention the vault in any CLAUDE.md or briefing. `ASIT_SMOKE_SECURITY=1` proves the listing carries no secret, the file sits outside the tasks tree, and no action verb reaches it.
17. **Embedded native windows are pixels, not context** (`src/main/services/appwindows.ts`). Win32 `SetParent` reparenting via koffi (prebuilt FFI — no compiler). A reparented child HWND paints above ALL Chromium content, so `setAllHidden` must banish them too or every overlay opens underneath. Original style/exStyle/parent are saved and restored on release, task delete, privacy move, and quit — **never leave a user's app parented to a dead process.** The AI cannot read these windows (no DOM); only the title is known, and the UI says so. User-driven only: no action verb exists.
18. **Shared memory is the one deliberately cross-workspace channel** (`src/main/services/memory.ts`). `Documents\ASIT\memory.md` holds short standing facts, injected into every task's CLAUDE.md and the Jarvis briefing so a fact taught in one workspace is known in all. Agents never write it with file tools — they dispatch `remember`/`forget` and MAIN appends, so workspace folder isolation is unbroken. Private workspaces neither contribute nor receive. Capped (40 facts) because it rides every turn.
19. **Scheduling is the only unattended actor** (`src/main/services/scheduler.ts`). A schedule is a prompt + firing rule (`once|hourly|daily|weekdays`) stored in `schedules` (migration 11); on fire it starts a normal agent turn via `startJarvisTurn`/`startWorkspaceChat`, so it inherits EVERY guardrail — critically, sends stay deny-by-default because `authorizeSendsFromUserMessage` runs on the schedule's prompt exactly as for a typed message, and an unattended loop must never message people. Missed runs roll FORWARD, never replay (a week offline must not dump seven briefings). One tick at a time, max 3 per tick. `ASIT_SMOKE_SECURITY=1` proves parsing, firing, roll-forward and the no-send property.
20. **Never `require('./relative')` in main-process code.** Rollup leaves a bare `require` untransformed, so in the bundled `out/main/index.js` it resolves against the output directory and throws MODULE_NOT_FOUND at runtime — usually inside a `try/catch` that silently swallows it, so the feature is simply dead in the packaged app while working in dev. Use a static `import`, or `await import('./x')` (which rollup does transform) when a cycle must be broken. Node builtins are fine either way.

21. **Browser-first shell rules.** The new-tab page is the sentinel `asit:newtab`: an NTP tab has NO pane (never `panes.open` it), so when active every view-backed sibling in its slot hides and plain DOM renders — the builtin-notes pattern; first navigation converts it in place. Web-tab ids come from ONE mint (`browser/useTabs.ts` `newWebTabId`) so scratch tabs survive the `scratchSave` layout handoff into a workspace. Search-engine URLs go through `shared/search.ts` only — never hardcode an engine (exception: quickfetch's `?g` scraper is deliberately Google-locked to its DOM). Bookmarks and history have **no action verb and no agent-facing IPC** — cross-workspace user data. `Settings.studyEnabled` gates study LAUNCHERS in the renderer only; main-side timer/lockdown machinery is untouched.

22. **Workflows are contained automations** (`src/main/services/workflows.ts`, migration 15). Identity comes from the workflow ROW (`task_id` → that workspace's agent; NULL → the universal agent's task), never the caller. `FLOW_FORBIDDEN` verbs + the `workspace` field are refused at save time AND run time; `{{param}}` substitutes into string VALUE fields only — never `action`/`kind`/`workspace`. Model steps run unattended: send authority cleared (never `authorizeSendsFromUserMessage` — a workflow prompt is not the user's live words), never Bash, and `beginUnattended(taskId)` strips flow-forbidden verbs from the action channel for the duration. Global workflows may not contain model steps. **No action verb can approve a confirm gate** — only `WORKFLOWS_CONFIRM` from a renderer click (absence doctrine, like session-stop). Runs survive panel close, not app restart (startup sweeps running → interrupted). Schedules can target a workflow; the no-send property holds for both schedule kinds. `./name` resolves workflow-first, then skill — in chat, watches, and the phone. `ASIT_SMOKE_WORKFLOWS=1` proves the engine; `ASIT_SMOKE_SECURITY=1` locks the walls.

23. **The context header is built from data the model never controls** (`src/main/services/context.ts`). Every chat/Jarvis turn gets a ~200-token owner-filtered header (open pane titles + FULL urls + snapshot age) via `paneManager.listForOwner` — page CONTENT stays pull-based on disk, framed as untrusted. Private tasks always yield an empty header (`ASIT_SMOKE_PANES=1` proves owner-scoping and private silence).

## Commands

- `npm run dev` — HMR dev
- `npm run typecheck` — both tsconfigs (run after changes)
- `npm run build` — production build to `out/`
- `npm run dist` — NSIS installer to `dist/`
- Headless smoke tests (after build): env `ASIT_SMOKE=1` | `ASIT_SMOKE_CHAT=1` | `ASIT_SMOKE_QGEN=1` | `ASIT_SMOKE_AGENT=1` | `ASIT_SMOKE_TRANSFER=1` | `ASIT_SMOKE_PANES=1` | `ASIT_SMOKE_COMPANION=1` | `ASIT_SMOKE_JARVIS=1` (needs logged-in CLI) | `ASIT_SMOKE_VOICE=1` (downloads ~130MB models on first run) | `ASIT_SMOKE_SECURITY=1` (agent-containment invariants) | `ASIT_SMOKE_TERMINAL=1` (terminal containment; spawns a real pty) | `ASIT_SMOKE_WORKFLOWS=1` (workflow engine: params, confirm gates, on_failure, live-pane conditions) with `npx electron out/main/index.js` (bottom of `src/main/index.ts`). Smoke runs are isolated: own userData (%APPDATA%\Electron) and documents redirected to temp — they must never touch real user data.
